## 2024-05-14 - Interactive Toggle Elements Accessibility
**Learning:** When building custom toggle elements (like payment status switches that toggle between true/false states), using a generic `onClick` on a `<div>` is inaccessible to both keyboard users (who can't focus or activate it with Space/Enter) and screen reader users (who don't know it's a switch or what its state is). While a `<button>` is better, using `role="switch"` along with `aria-checked={boolean}` perfectly communicates the exact binary nature of the control to assistive technologies. Additionally, when a parent element like a button has an `aria-label`, its child elements' attributes may be ignored by screen readers, so all necessary state information must be contained within that label, and child elements should have `aria-hidden="true"`.
**Action:** Always replace interactive `<div>` toggles with semantic `<button type="button" role="switch" aria-checked={state}>` elements. Ensure they have clear `aria-label` descriptions that include state context, apply `aria-hidden="true"` to decorative child elements, and include robust focus styles (e.g., `focus-visible:ring-2`) for keyboard accessibility.
